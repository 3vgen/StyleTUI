# Общие принципы дизайна TUI

Словарь приёмов. Framework-agnostic: применимо к ratatui, Textual, Cursive,
Bubble Tea и т.д. Каждый пункт — принцип + «почему» + «как проверить».

## 1. Философия

- **Клавиатура первична, мышь — бонус.** Все действия достижимы с клавиатуры;
  клик — удобство, а не опора. Клавиши — vim-семантика (`j`/`k`, `gg`/`G`,
  `h`/`l`, `?`, `q`/`Esc`, `Enter`).
- **Минимализм.** Никаких лишних рамок, теней, декора. Каждая строка несёт
  информацию или навигацию.
- **Мгновенный фидбек.** Любое действие сразу отражается: спиннер/`…` при
  фоновой работе, тост при результате, бейдж при смене состояния.
- **Состояние видно всегда, без отдельного «экрана статуса»** — через бейджи и
  цвет строки.

## 2. Раскладка

Базовые паттерны (по возрастанию сложности):

| Паттерн | Что это | Когда |
|---|---|---|
| **Список + статус-бар** | список сущности + однострочный статус | почти всегда, минимум |
| **Master-detail** | список слева, детали выбранного справа/снизу | у элемента есть много полей |
| **Две панели** | список + логи/консоль | нужен поток событий |
| **Оверлеи-модалки** | настройки/подтверждения поверх | второстепенные экраны |
| **Тост** | временное уведомление справа-сверху | результат действия |

Правила:

- **Основная сущность — список** в главной области; не размазывай её по вкладкам.
- **Глобальное состояние — нижний статус-бар** (всегда видим).
- **Вторичное/переходное — справа или как оверлей**, не в основном списке.
- **Оверлеи центрированы**, тосты — справа сверху (не конкурируют за фокус).
- **Минимальный размер** + честный fallback: если терминал меньше порога — одно
  сообщение «too small», а не рассыпавшийся макет.
- **Деградация на узких экранах**: лишние панели скрываются, а не сжимаются до
  нуля (например, при ширине < N колонок панель логов прячется).

## 3. Цвет и темы

- **Семантические роли, а не буквальные цвета.** Виджеты обращаются к
  `accent` / `success` / `error` / `warning` / `muted` / `border` / `selected` /
  `background` — тема решает, какие это RGB. Никогда не хардкодить hex в виджете.
- **Палитра** — один источник правды: `background`, `foreground`, `accent`,
  `selection_*`, и 16 ANSI-цветов. Темы выводятся из палитры.
- **Производные цвета — смешиванием** (`mix`/`lerp`), а не вторым набором
  констант: «затемнённый зелёный» для выбранного+активного = `mix(green, bg, 0.75)`.
- **Фон заливается один раз** на весь кадр; виджеты ставят только `fg` — клетки
  без явного `bg` наследуют палитру.
- **Контраст — тестом**: у каждой темы отношение luminосы fg/bg ≥ 3.0.
- **Синхронизация с терминалом** (OSC 10/11) — чтобы поля вне сетки совпадали с
  палитрой (опционально).

## 4. Виджеты и блоки

### Список (основная сущность)
- **Строки**: выделение — фон (`selected`); «активный» элемент — семантический
  цвет (`success`); «выбранный + активный» — смешанный (`selected_connected`).
- **Выравнивание колонок** по фиксированной ширине (имя, тип, адрес, метрика) —
  глобально по всем строкам, не «плавает».
- **Обрезка** по видимой ширине (учитывая wide-символы) с `…`.
- **Дерево-префиксы** `├ `/`└ ` для иерархии; заголовки групп между строками.
- **Пустое состояние** — подсказка-действие, а не пустой экран.

### Статус-бар
- **Слева**: бейдж состояния (` CONNECTED `/` … `) + имя активного элемента
  (обрезанное).
- **Справа**: компактные бейджи настроек/состояния акцентом.
- **Приоритетное обрезание**: при нехватке ширины правые бейджи удаляются по
  возрастанию приоритета; состояние не сжимается.

### Бейджи состояния
Цветная «пилюля»: состояние = фон (`success`/`warning`/серый), текст = fg. Один
виджет, один смысл — «подключено / в процессе / отключено».

### Модалки (оверлеи)
Центрированные, с рамкой; `h`/`l` (или `←`/`→`) — менять значение, `Enter` —
подтвердить, `q`/`Esc` — отменить. Активный пункт — `success` (жирный).

### Тост
Временное уведомление справа сверху; info — акцентная рамка, error — красная;
текст переносится; не занимает место в статус-баре.

## 5. Взаимодействие

- **Модель фокуса**: ровно одна активная панель; её рамка — акцентом, остальные —
  `border` (приглушённо). Переключение — `h`/`l` или `←`/`→`.
- **Один оверлей за раз**; `q`/`Esc` всегда отменяет ближайший уровень.
- **Обратимость выхода**: `q`/`Esc` отсоединяет UI, но не убивает фоновый
  демон/состояние; полный выход — отдельная команда (`Ctrl+C`).
- **Справка** (`?`) — полная карта клавиш; без неё интерфейс не «открываем».
- **Live-фидбек фоновой работы**: спиннер/`…` в строке или панели, а не блокировка.

## 6. Видимость состояния

- «Выбрано» (курсор) ≠ «активно» (семантическое состояние) — два разных сигнала.
- Глобальные переключатели (kill switch, auto-connect) — бейджи в статус-баре.
- Результат действия — тост (успех/ошибка) сразу, а не только в логах.

## 7. Производительность

- **Immediate-mode** (ratatui/Bubble Tea) предпочтителен: перерисовка только
  изменённых ячеек, нет оверхеда реактивного дерева.
- **Перерисовывать по изменению** (dirty-трекинг), не по таймеру.
- **Фоновая работа — в отдельном потоке/процессе**, UI не блокируется; результат
  приходит сообщением.
- **Меньше перерисовок на слабых каналах** (SSH): не перерисовывать всю таблицу,
  если меняется одна строка.

## 8. Устойчивость и крайние случаи

- **Минимальный размер** + сообщение вместо сломанного макета.
- **Пустое состояние** списка — инструкция, что делать.
- **Обрезка/перенос** длинных строк без вылета за границу.
- **Переполнение метрик** — фиксированная ширина + маркер переполнения (`>9 EB`).
- **Фолбэк темы** — если имя темы неизвестно, дефолтная палитра, не краш.

## 9. Чеклист (перед реализацией)

1. Какая **основная сущность**? → список.
2. Какие **действия** над ней? → клавиши + `?`-справка.
3. Какое **глобальное состояние**? → статус-бар (бейджи).
4. Какая **вторичная информация**? → панель деталей / логов.
5. Какие **настройки/подтверждения**? → модалки.
6. Какая **фоновая работа**? → спиннер + тост.
7. Какая **палитра** и **семантические роли**? → не буквальные цвета.
8. Какая **раскладка и клавиши**? → vim-семантика + модель фокуса.
9. Какие **крайние случаи**? → min-size, empty state, truncation.
