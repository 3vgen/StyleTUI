# Design-system: раскладка, цвета, виджеты

Точное описание визуальной системы kvn. Источник — `src/ui/{layout,widgets,styles,palette}.rs`.

## 1. Раскладка

Верхнеуровневый вертикальный сплит (`draw_impl` в `layout.rs`):

```
Constraint::Length(3)   — панель трафика (только при подключённом VPN)
Constraint::Min(0)      — основной контент
Constraint::Length(1)   — статус-бар
```

- **Панель трафика** (высота 3 = контент + верх/низ рамки) рисуется только когда
  VPN подключён; иначе верхняя зона схлопывается (пустой `Length(0)`).
- **Основной контент** — горизонтальный сплит 50/50: `Profiles` (слева) и `Logs`
  (справа). При ширине < 90 колонок (`TWO_PANE_MIN_WIDTH`) Logs скрывается,
  Profiles занимает всю ширину.
- **Статус-бар** — одна строка внизу.
- **Оверлеи** (справка, подтверждение удаления, роутинг, geo-регион, DNS, тема,
  сервис-роутинг, поддержка, миграция) рисуются поверх, центрированные.
- **Тост** — временное уведомление справа сверху (поверх всего, кроме некоторых
  оверлеев).

### Пороги размера терминала

- Минимум **70×15** (`MIN_TERMINAL_WIDTH`/`MIN_TERMINAL_HEIGHT`). Меньше —
  выводится сообщение «terminal too small».
- Две панели — от **90** колонок.

### Рамки панелей

- У панелей 1px-рамка (`Borders::ALL`), заголовок через `.title(" Profiles ")`.
- **Фокус** панели подсвечивается акцентом: у активной панели рамка `accent()`
  (жирный), у неактивной — `border()` (приглушённый).

## 2. Цвета и темы

### Палитра (`Palette`)

```
accent, cursor, foreground, background,
selection_foreground, selection_background,
ansi: [16]  — 16 ANSI-цветов
```

- Загружается на этапе сборки: `build.rs` парсит `themes/*.toml` в статическую
  таблицу `BUNDLED` (без runtime-парсинга TOML).
- **22 темы** (Omarchy 4): catppuccin, tokyo-night, gruvbox, nord, rose-pine,
  everforest, kanagawa, miasma, matte-black, vantablack, white, … + `legacy`
  (фолбэк: cyan-акцент, gray-текст, black-фон, named ANSI).
- `Palette::lookup(slug)` — поиск по snake-case имени; неизвестное имя → `legacy`.

### Формат темы (`themes/*.toml`)

Семантическая схема Omarchy `colors.toml`:

```toml
mode = "dark"
accent = "#7aa2f7"
selection = "#292e42"
muted = "#414868"
background = "#1a1b26"
foreground = "#a9b1d6"
bright_foreground = "#c0caf5"
red/yellow/green/cyan/blue/magenta = "#…"
bright_red/bright_yellow/bright_green/bright_cyan/bright_blue/bright_magenta = "#…"
```

Маппинг в `ansi[16]`: `[0]=background, [1]=red, [2]=green, [3]=yellow,
[4]=blue, [5]=magenta, [6]=cyan, [7]=foreground, [8]=muted, [9..14]=bright_*,
[15]=bright_foreground`.

### Семантические стили (`Theme`)

| Метод | Описание | Что в `legacy` |
|---|---|---|
| `accent()` | акцент (заголовки, хинты, бейджи настроек) | cyan + BOLD |
| `normal()` | обычный текст | gray |
| `muted()` | приглушённый (метаданные логов, таймстемпы) | `ansi[8]` (dark gray) |
| `error()` | ошибки | red + BOLD |
| `success()` | успех / подключено | green + BOLD |
| `warning()` | предупреждения | yellow + BOLD |
| `border()` | рамки (не в фокусе) | `ansi[8]` |
| `selected()` | выбранная строка | bg = selection_background, fg = selection_foreground, BOLD |
| `selected_connected()` | выбранная + активное подключение | bg = `mix(green, background, 0.75)`, fg = green, BOLD |
| `connected_badge()` | бейдж «подключено» | fg = background, bg = green, BOLD |
| `connecting_badge()` | бейдж «подключение» | fg = background, bg = yellow, BOLD |
| `offline_badge()` | бейдж «отключено» | fg = foreground, bg = `mix(foreground, background, 0.75)`, BOLD |
| `status_bar()` | фон статус-бара | fg = foreground, bg = `mix(foreground, background, 0.92)` |
| `popup_bg()` | фон попапов | background |
| `background()` | фон всего кадра | background |

### Принципы цвета

1. **Никаких хардкод-цветов в виджетах** — только `Theme`-методы.
2. **Смешивание вместо второй палитры**: `mix(a, b, t)` (линейная интерполяция в
   sRGB) выводит «затемнённый» фон бейджа/статус-бара из `foreground` и
   `background` — отдельный цвет не вводится.
3. **Фон кадра заливается первым** (`draw()` рисует `Block` со стилем
   `background()`), а виджеты ставят только `fg` — так клетки без явного `bg`
   наследуют палитру, а не дефолт терминала.
4. **OSC 10/11** синхронизируют fg/bg терминала с палитрой (при выходе —
   OSC 110/111 восстанавливают).
5. **Контраст гарантирован тестом**: у каждой встроенной темы отношение
   luminosых fg/bg ≥ 3.0.

## 3. Виджеты

### StatusBar (одна строка, низ)

- **Слева**: бейдж состояния + имя активного профиля (обрезанное).
  - ` CONNECTED ` / ` CONNECTING ` / ` DISCONNECTED ` — жирный, с цветным фоном
    (зелёный/жёлтый/серый).
  - Имя профиля — `normal()`, обрезается `truncate_to_width()`.
- **Справа**: бейджи настроек акцентом: `KS` (kill switch), `Auto`
  (auto-connect), вид DNS (`DoH`/`DoT`/`DoQ`/`UDP`/`TCP`/`local`/`fakeip`),
  режим роутинга (`Global`/`BypassRu`/…), бейдж свежести rule-set
  (`(1d) 14 Aug 10:20` / `updating…` / `never`).
- **Приоритетное обрезание**: при нехватке ширины справа-элементы удаляются по
  возрастанию приоритета (KS держится первым). Бейдж состояния не сжимается.
- Фон всей строки — `status_bar()` (слегка отделён от фона подмешиванием
  foreground).

### Traffic panel (сверху, только при VPN)

- Колонки с **фиксированной шириной** (выравнивание не «прыгает»):
  - скорость `↑`/`↓`: 8 (`format_bps_field`, 1024-базовые единицы);
  - суммарный трафик: 6 (`format_bytes_field`);
  - число соединений: 6.
- Формат скоростей: `0.0 KB/s`, `1.4 MB/s` (всегда ≥ KB/s для выравнивания).
  Переполнение: `>9 EB/s`.

### Строка профиля (список Profiles)

- **Префикс дерева**: `├ ` для всех, кроме последнего (`└ `) — иерархия читается
  как дерево.
- **Колонки**: `имя` (гибкая, обрезается) + `протокол` (6 симв., бейдж типа
  `VLESS`/`VMESS`/`SS`/…) + `address:port` (11–21, выравнивается глобально по
  всем строкам) + `latency` (7, ` 1234ms` / ` err` / ` …` при тесте).
- **Состояния**:
  - выбранная — `selected()` (фоновый highlight);
  - подключённая — `success()` (зелёная);
  - выбранная + подключённая — `selected_connected()` (затемнённый зелёный фон);
  - обычная — `normal()`.
- **Заголовок подписки**: строка `Subscription: <имя> <расписание>` между
  группами профилей; при выборе — `selected()`.

### Toast (временное уведомление, справа сверху)

- `Clear` + рамка (`Borders::ALL`), отступ по горизонтали 1.
- Info — рамка акцентом, Error — `error()` (красным).
- Текст переносится (`Wrap { trim: true }`), макс. ширина ~50, высота 3–4.
- Не рисуется на слишком маленьком терминале (<12×5).

## 4. Типографика и отступы

- **Обрезка по видимой ширине** (`truncate_to_width`, `fit_to_visual_width`) —
  учитывает широкие символы (unicode-width), добавляет `...`.
- **Выравнивание по ширине с паддингом** (`pad_to_visual_width`) — колонки
  таблиц держат одинаковую ширину.
- **Человекочитаемые величины**: 1024-базовые (`KB`/`MB`/…), фиксированная
  ширина поля, суффикс `/s` у скоростей.
- Рамки панелей — одинарные (`Borders::ALL`), без вертикальных разделителей
  между колонками (разделитель — пробелы).
- Заголовки панелей/оверлеев — в рамке с отступом (`" Title "`).

## 5. Правила для переноса стиля (чеклист)

1. Никаких хардкод-цветов в виджетах — только семантические роли из темы.
2. Палитра = 16 ANSI + 6 семантических; темы грузятся статически на сборке.
3. Фон заливается один раз на весь кадр; виджеты ставят `fg`.
4. Производные цвета — через `mix()`, а не второй набор констант.
5. Фиксированная ширина колонок + приоритетное обрезание вместо «плывущего»
   макета.
6. Состояния — семантические бейджи (success/warning/error), а не произвольные
   цвета.
7. Дерево-префиксы (`├ `/`└ `) для иерархических списков.
8. Оверлеи — центрированные модалки; тосты — временные справа сверху.
9. Пороги минимального размера + корректный fallback «terminal too small».
