# Workflow: «задача → дизайн TUI»

Пошаговый процесс, как из описания задачи получить структуру TUI. Применим к
любому инструменту и фреймворку. В конце — разобранный пример.

## Шаг 0. Сформулировать сущность и состояние

Ответь на два вопроса:

1. **Что является «единицей» задачи?** (профиль, контейнер, задача, запись, чек
   листа…) — это станет списком.
2. **Какое глобальное состояние?** (подключено/нет, активно/выключено, очередь
   пуста/заполнена…) — это статус-бар.

## Шаг 1. Список — колонки

Для каждой строки выпиши 2–5 полей, которые важны при беглом взгляде, и
определи порядок/ширину:

| Поле | Тип | Ширина | Замечание |
|---|---|---|---|
| имя | текст | гибкая | обрезается |
| тип/бейдж | enum | фикс. | короткий код |
| адрес/ключ | текст | фикс. (выравнивается глобально) | |
| метрика | число | фикс. | `ms`, `%`, `MB` |

Правило: имя — самое главное (слева), метрики — справа, фикс. ширина.

## Шаг 2. Действия → клавиши

Составь таблицу «действие → клавиша». Старайся придерживаться vim-семантики:

- `j`/`k` (или `↓`/`↑`) — навигация, `gg`/`G` — края.
- `Enter` — главное действие (подключить/открыть/выполнить).
- `e` — редактировать, `d` — удалить, `y` — копировать, `p` — вставить.
- `r` — повторить/перезапустить, `s` — остановить, `t` — тест, `T` — тест всех.
- `a` — toggle автодействия, `m`/`o`/`D`/`S`/`C` — настройки (по первой букве).
- `?` — справка, `q`/`Esc` — назад/выход, `Ctrl+C` — полный выход.
- `h`/`l` (или `←`/`→`) — переключение панелей/значений в модалке.

Каждую клавишу зафиксировать в `?`-справке.

## Шаг 3. Глобальное состояние → статус-бар

Определи, что должно быть видно **всегда**:

- бейдж состояния слева (состояние системы/активного элемента);
- имя активного элемента;
- бейджи переключателей справа (режим, авто-действия, ключевые настройки).

## Шаг 4. Вторичная информация → панель

Если у элемента много деталей или есть поток событий — добавь вторую панель:

- детали выбранного (справа) — для полей, не влезающих в строку списка;
- логи/консоль (справа/снизу) — для истории событий.

## Шаг 5. Настройки и подтверждения → модалки

Всё, что не используется постоянно, выноси в центрированные модалки, а не в
отдельные экраны: выбор режима, формы, подтверждение удаления.

## Шаг 6. Фоновая работа → спиннер + тост

Любое действие дольше ~200 мс: спиннер/`…` в строке (живой фидбек) + тост по
завершении (успех/ошибка). UI не блокировать.

## Шаг 7. Палитра и роли

Определи семантические роли (не цвета): `accent`, `success`, `error`, `warning`,
`muted`, `border`, `selected`, `background`. Подбери палитру под них. Производные
оттенки — смешиванием.

## Шаг 8. Раскладка и пороги

Собери вертикаль: `[верхняя панель?] + [основной контент] + [статус-бар]`.
Задай пороги: минимальный размер (сообщение «too small»), ширину, при которой
прячется вторая панель.

## Шаг 9. Крайние случаи

Пустой список, длинные строки (обрезка), переполнение метрик, неизвестная тема
(фолбэк), потеря соединения с фоновым процессом.

## Разобранный пример: «TUI для управления Docker-контейнерами»

**Шаг 0.** Сущность = контейнер; состояние = «сколько запущено/остановлено»,
плюс глобально — работает ли Docker daemon.

**Шаг 1.** Список `docker ps -a`: колонки `имя` (гибкая) · `статус` (Up/Exited,
бейдж) · `image` (фикс.) · `CPU%` · `MEM` (фикс., справа).

**Шаг 2.** Клавиши:
- `j`/`k`, `gg`/`G` — выбор; `Enter` — логи контейнера (главное действие);
- `r` — restart, `s` — stop, `S` — start, `d` — rm (с подтверждением), `R` — restart all;
- `e` — exec-шелл, `p` — port map;
- `f` — фокус на панель логов, `?` — справка, `q` — выход.

**Шаг 3.** Статус-бар: слева ` RUNNING ` / ` DOCKER DOWN ` (бейдж) + число
`3 up / 2 exited`; справа бейдж `auto-start` (если включён).

**Шаг 4.** Вторая панель — логи выбранного контейнера (поток событий).

**Шаг 5.** Модалка подтверждения `rm`, модалка настроек (автозапуск, prune).

**Шаг 6.** `restart`/`pull` — спиннер в строке + тост «Container X restarted».

**Шаг 7–9.** Роли/палитра/пороги — по `principles.md`.

Итоговая раскладка:

```
┌─ Containers ────────────────┬─ Logs: myapp ───────────────────┐
│ ├ myapp   Up    nginx  2%   │  …                              │
│ ├ db      Up    pg16   1%   │                                 │
│ └ worker  Exited redis 0%   │                                 │
├─────────────────────────────┴─────────────────────────────────┤
│ RUNNING  3 up / 2 exited        auto-start                    │
└────────────────────────────────────────────────────────────────┘
```
